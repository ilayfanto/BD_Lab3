# ЛР3 — ИИ для обнаружения DDoS-атак (PostgreSQL + Python)

Продолжение ЛР2. Сохранено всё из ЛР1 и ЛР2: создание схемы, ввод данных, ограничения, ссылочная целостность, ALTER TABLE, конструктор SELECT, поиск LIKE/regex, строковые функции, мастер JOIN, лог. Добавлены подзапросы, пользовательские типы, NOT SIMILAR TO, CASE, COALESCE и NULLIF.

## Стек
- Python 3.12+ (проверено на 3.15), PySide6, psycopg2
- PostgreSQL 13+ (проверено на 19)
- ОС: Windows / Linux / macOS

## Запуск
```
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```
Подключение задаётся в `config.ini`: localhost:5432, БД `ddos_lab3`, postgres/postgres. Если базы нет, она создаётся при подключении. Порядок работы: «Подключиться» → «Создать схему и таблицы» → «Добавить демо-данные».

## Что добавлено в ЛР3
1. **Фильтры на основе подзапросов** — вкладка «Подзапросы» в окне «Показать данные». Условие собирается из выпадающих списков:
   - вид условия: `IN`, `NOT IN`, `оператор ANY`, `оператор ALL`, `EXISTS`, `NOT EXISTS` или скалярный подзапрос с агрегатом;
   - таблица и столбец подзапроса;
   - фильтр внутри подзапроса;
   - флажок «коррелированный» связывает подзапрос с текущей строкой внешней таблицы (`i.поле = o.поле`). Поля связи подставляются по внешним ключам.

   Условий можно добавить несколько и объединить через AND/OR. В списке «Пример» есть 7 готовых сценариев: например, «модели без экспериментов» (NOT EXISTS) и «запуски не хуже среднего по своему эксперименту» (коррелированный скалярный).
2. **Пользовательские типы** — отдельное окно, кнопка «Пользовательские типы» в главном окне.
   - Просмотр всех типов схемы (ENUM, составные, DOMAIN): значения или поля и в каких столбцах используется тип.
   - Создание ENUM, составного типа и DOMAIN с CHECK.
   - Управление: добавить значение ENUM (в конец, BEFORE или AFTER), переименовать значение, добавить или удалить поле составного типа, переименовать тип, удалить тип (с CASCADE).
   - Создание таблицы со столбцами пользовательских типов, вставка строк (для ENUM — выпадающий список, для составного типа — подсказка формата `(поле1,поле2)`) и просмотр. Поля составного типа раскрываются в отдельные столбцы: `(owner).team`.
   - Новые типы доступны и в окне ALTER TABLE.
3. **SIMILAR TO / NOT SIMILAR TO** — во вкладке поиска по тексту, с подсказкой по синтаксису. Кнопка «Проверить строку» показывает, подходит ли своя строка под шаблон (TRUE/FALSE).
   **Агрегирование и группировка** — в конструкторе SELECT: COUNT, SUM, AVG, MIN, MAX, а также STRING_AGG; GROUP BY по столбцам и вычисляемым столбцам; HAVING.
4. **Конструктор CASE** — в конструкторе SELECT, блок «Вычисляемые столбцы». Условия WHEN … THEN … задаются строками формы, есть ELSE. Результат становится новым столбцом, по нему можно группировать (например, `COUNT(*)` по уровню качества F1).
   **COALESCE и NULLIF** — в том же блоке: подстановка значения вместо NULL (с запасным столбцом и приведением к тексту) и замена совпадающего значения на NULL.

Все запросы собираются без ручного SQL. Готовый SQL показывается перед выполнением, ошибки выводятся понятными сообщениями с ROLLBACK.

## Структура БД (схема `ddos_ai`)
| Таблица | Назначение | Ключи и ограничения |
|---|---|---|
| `models` | модели ИИ | PK, UNIQUE(name), CHECK, ENUM `model_family`, `tags text[]` |
| `datasets` | датасеты трафика | PK, UNIQUE(name), CHECK, `attack_types attack_type[]` |
| `experiments` | эксперименты | FK → models (RESTRICT / CASCADE), FK → datasets (SET NULL), UNIQUE(title, model_id) |
| `runs` | запуски | FK → experiments (CASCADE), UNIQUE(experiment_id, run_no), CHECK метрик 0..1 |

## Логирование
`app.log`: INFO/ERROR с временными метками — подключения, DDL (включая CREATE/ALTER/DROP TYPE), DML, SELECT, COMMIT/ROLLBACK, ошибки.

## Файлы
- `app.py` — главное окно, формы ввода, окно вывода данных
- `lab2.py` — окна ЛР2: ALTER TABLE, конструктор SELECT, поиск, мастер JOIN, строковые функции
- `lab3.py` — окна ЛР3: подзапросы, пользовательские типы, CASE / COALESCE / NULLIF
- `builders.py` — безопасная сборка SQL (`psycopg2.sql`, экранирование имён и значений)
- `db.py` — подключение, транзакции, чтение структуры БД и типов, понятные сообщения об ошибках, лог
- `schema.sql` — DDL-скрипт
- `config.ini` — параметры подключения
